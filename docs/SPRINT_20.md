# Sprint 20 — Security Hardening

## النطاق المنفذ

تمت تقوية التفويض على الخادم دون الاعتماد على إخفاء الأزرار أو المسارات في الواجهة. أضيفت سياسات واضحة للعمليات الحساسة داخل `apps/accounts/permissions.py`، تشمل إنشاء وإصدار البيع، اعتماد الشراء، إنشاء واستلام التحويل، إغلاق الوردية، وعرض التقارير.

تم تطبيق عزل الفروع على واجهات المشتريات والمبيعات والورديات، وعلى نقاط API الحساسة. الاستعلامات المقيدة بالفرع تستخدم object-level scoping قبل `get_object_or_404`؛ لذلك لا يكشف الوصول المباشر إلى معرّف كائن في فرع آخر وجود ذلك الكائن، ويعيد `404`.

تم تعزيز الخدمات نفسها، وليس الواجهات فقط، بحيث تتحقق خدمة البيع والمشتريات والتحويلات والإغلاق والمصروفات والهدر من الدور والفرع. هذا يمنع تجاوز الصلاحيات عند استدعاء الخدمة من مسار آخر أو من API مختلف.

## إعدادات Django الأمنية

أصبح `DEBUG` معطلًا افتراضيًا، ويطلب النظام `DJANGO_SECRET_KEY` صراحة في بيئة الإنتاج. أضيفت متغيرات `DJANGO_ENV` و`DJANGO_CSRF_TRUSTED_ORIGINS`، مع `SameSite=Lax` للكوكيز، وخصائص HSTS وCross-Origin في وضع الإنتاج. بقي `X-Frame-Options` وReferrer Policy وContent-Type nosniff مفعلة.

تمت إضافة تحقق من مرفقات المصروفات في النموذج وAPI؛ الأنواع المسموحة PDF وJPG وPNG، والحد الأقصى 5 ميجابايت. لم تتم إضافة CORS لأن النظام لا يحتاج cross-origin API في هذا الـ Sprint، وأي إضافة مستقبلية يجب أن تكون بقائمة origins صريحة وليست wildcard.

## Audit

تم توسيع التسجيل للعمليات الحساسة بإضافة أحداث اعتماد ورفض الإغلاق، إرسال واستلام التحويل، وإلغاء الهدر، مع actor وobject وbefore/after عند انتقال الحالة. التسجيل العام للطلبات المعدّلة ما زال يعمل عبر `AuditRequestMiddleware` مع request ID وIP.

## الاختبارات والتحقق

تمت إضافة اختبارات الوصول غير المصادق، منع تصعيد كاشير إلى كتابة الكتالوج، منع الوصول المباشر إلى كائن فرع آخر، ومنع إصدار بيع فرع آخر. شغلت فحوصات Django داخل Docker/PostgreSQL ونجحت جميع الاختبارات الحالية.

```text
python manage.py check --deploy: 0 issues with a generated production-length secret
python manage.py check: OK
pytest: 21 passed
python -m compileall: OK
git diff --check: OK
```

## ملاحظات تشغيلية

ملف `.env.example` أصبح يوضح وضع الإنتاج ويطلب سرًا عشوائيًا طويلًا. يجب عدم استخدام القيم الوهمية في الإنتاج، ويجب ضبط `DJANGO_ALLOWED_HOSTS` و`DJANGO_CSRF_TRUSTED_ORIGINS` على النطاقات الفعلية فقط.
