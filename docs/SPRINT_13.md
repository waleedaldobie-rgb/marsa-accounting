# Sprint 13 — Hardening, Sales Returns & Audit

## الهدف
تقوية العمليات الحساسة، إضافة مرتجعات المبيعات، وربط العمليات المالية/المخزنية المهمة بسجل التدقيق.

## المنجز
- SalesReturn / SalesReturnItem.
- اعتماد المرتجع يعيد الوزن الخام للمخزون بحركة SALES_RETURN.
- اعتماد المرتجع ينشئ حركة مالية OUT للاسترداد.
- منع تجاوز إجمالي الكمية المباعة عبر عدة مرتجعات معتمدة.
- تحويل الفاتورة إلى REFUNDED عند إرجاع كامل الكميات الخام.
- إلغاء المرتجع قبل الاعتماد فقط.
- صلاحيات المبيعات والتفاصيل والـPOS أصبحت صريحة.
- Audit events لإصدار البيع واعتماد/إلغاء الهدر والمصروف والمرتجعات.
- إضافة تواريخ المعتمد/الملغي للمصاريف.
- Request-ID middleware موجود ويُمرر إلى AuditLog عند توفر request.

## قواعد مهمة
- المرتجع لا يغير المخزون قبل الاعتماد.
- لا يمكن حذف فاتورة أو مرتجع معتمد.
- مبلغ الاسترداد للمرتجع الخام يحسب بنسبة المبلغ المباع إلى الوزن الخام المباع؛ هذا يمنع ربط الاسترداد تلقائيًا بفرق التنظيف.
- جميع العمليات الحساسة تستخدم transaction.atomic وselect_for_update حيث يلزم.

## التحقق
تم إجراء فحص Syntax لملفات Python. لم يتم تشغيل اختبارات Django/PostgreSQL runtime في بيئة البناء الحالية.
