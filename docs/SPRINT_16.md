# Sprint 16 — Production Hardening

## الهدف
تقوية النسخة قبل تشغيلها على بيئة Django/PostgreSQL حقيقية، مع معالجة اتساق النقدية وبعض أخطاء التشغيل الصغيرة، وإضافة فحص صحة للخدمة.

## ما تم تنفيذه
- ربط المصروف بحقل `shift` اختياري.
- المصروف النقدي المعتمد يجب أن يرتبط بورديّة مفتوحة من نفس الفرع، وتُسجّل حركة `PaymentTransaction` على تلك الوردية.
- المصروفات غير النقدية يمكن أن تبقى بدون وردية.
- إصلاح redirects غير صالحة في صفحات المصاريف كانت تعتمد على متغير `name` غير موجود.
- تنظيف استخدام `Sum` في مرتجعات المبيعات بدل الاستيراد الديناميكي.
- إضافة endpoint عام `GET /health/` لفحص التطبيق واتصال PostgreSQL وإرجاع `200` عند الجاهزية أو `503` عند تعذر قاعدة البيانات.
- إضافة إعدادات أمنية إضافية قابلة للضبط عبر البيئة: proxy SSL header، `X-Frame-Options`، وReferrer Policy.
- فحص Syntax لجميع ملفات Python بعد التعديلات.

## ملاحظات مهمة
- لم يتم إنشاء أو تطبيق migrations في بيئة البناء الحالية لأن Django/PostgreSQL runtime غير متاحين هنا.
- تغيير `Expense.shift` يحتاج migration عند تشغيل المشروع محليًا.
- يجب تنفيذ `python manage.py makemigrations` ثم `python manage.py migrate` في البيئة الفعلية.
- بعد ذلك يجب تشغيل اختبارات Django/PostgreSQL الفعلية وUAT.

## بوابة القبول التالية
1. تشغيل PostgreSQL.
2. `python manage.py check`
3. `python manage.py makemigrations`
4. مراجعة migration الناتجة.
5. `python manage.py migrate`
6. `python manage.py test`
7. اختبار `/health/`.
8. اختبار دورة: شراء → مخزون → نقل → بيع → إغلاق وردية → تقرير.
9. اختبار مصروف نقدي مرتبط بوردية ومصروف غير نقدي.
10. اختبار الصلاحيات والحظر بين الفروع.
11. أخذ backup واستعادة تجريبية قبل اعتبار النظام جاهزًا للإنتاج.
